## Website Content Guidelines

### Do

- Keep copy concise and professional
- Use concrete, technical language
- Maintain honest solo consultant positioning
- Focus on outcomes and deliverables
- Include clear CTAs on every page
- Keep services specific and actionable

### Don't

- Don't invent clients, logos, or testimonials
- Don't overstate company size or capability
- Don't use vague buzzwords without explanation
- Don't add features before they're needed
- Don't create case studies without real projects
- Don't claim partnerships that don't exist

## LinkedIn Content Strategy

### Post Types

| Type                     | Frequency | Example                                                      |
| ------------------------ | --------- | ------------------------------------------------------------ |
| **Quick tip**            | 2/week    | "One thing I always check when reviewing a data pipeline..." |
| **Lesson learned**       | 1/week    | "A project I worked on had X problem. Here's what we did..." |
| **Architecture insight** | 1–2/month | "Why I recommend starting with X before Y..."                |
| **Opinion**              | 1/month   | "I think [tool] is overused for [use case]. Here's why..."   |
| **Question**             | 1–2/month | "What's the hardest part of scaling data pipelines?"         |

### Content Topics

- Data architecture patterns
- Common data platform mistakes
- Spark / Airflow / Kafka / Dagster tips
- Data quality approaches
- Platform ownership and handover
- Build vs buy decisions
- Cost optimization
- Team structure
- Tool selection
- Cloud platform decisions (AWS, Azure)

### Post Structure

1. **Hook** (1–2 lines) — grab attention
2. **Context** (2–3 lines) — set up the problem
3. **Insight** (3–5 lines) — share the main point
4. **Takeaway** (1–2 lines) — what to do with this
5. **Engagement** (optional) — ask a question

### Tone

- Professional but human
- Technical enough for practitioners
- Accessible for leadership
- Opinionated but not arrogant
- Practical over theoretical

- [ ] Canonical URL

## Risks to Avoid

| Risk                     | Mitigation                                    |
| ------------------------ | --------------------------------------------- |
| Over-engineering website | Keep it simple, add features only when needed |
| Fake credibility signals | Never invent clients, logos, testimonials     |
| Inconsistent posting     | Batch create content, use reminders           |
| Stale LinkedIn profile   | Review monthly, update Featured as needed     |
| Domain issues            | Test thoroughly before switching              |
| SEO obsession            | Focus on content quality first                |
