# Case Study Collection Plan

## Why Case Studies Matter

Case studies are the #1 trust-building asset for consulting:

| Asset            | Trust Level | Effort           |
| ---------------- | ----------- | ---------------- |
| Website copy     | Low         | Low              |
| Blog posts       | Medium      | Medium           |
| **Case studies** | High        | Medium           |
| Testimonials     | Very High   | Low (if you ask) |
| Referrals        | Highest     | Zero (earned)    |

**Without case studies, you're saying "trust me."**
**With case studies, you're saying "look at what I did."**

---

## Types of Case Studies

### Type 1: Named Case Study (Gold Standard)

**What it is:** Client name, logo, specific details, testimonial quote.

**Example:**

> "How seniuts.com helped TechCorp reduce Databricks costs by 35%"
>
> Logo: [TechCorp]
> Quote: "Vasili's audit saved us €60k annually." — Jane Doe, CTO

**When possible:**

- Client agrees to be named
- NDA allows or is waived for marketing
- Results are concrete and verifiable

**How to get:**

- Ask explicitly during project wrap-up
- Offer draft for client approval
- Make it easy (you write, they approve)

---

### Type 2: Anonymized Case Study (Silver — Most Common)

**What it is:** Industry, company size, problem, solution, results — but no name.

**Example:**

> "AdTech Platform: 25% Databricks Cost Reduction"
>
> Client: A European AdTech company processing 70–80TB/day
> Challenge: Spark compute costs growing faster than revenue
> Solution: Cluster optimization, incremental processing, partition tuning
> Result: 25% cost reduction, maintained SLAs

**When to use:**

- Client won't allow name (common)
- NDA prohibits disclosure
- Client is in stealth mode
- Sensitive industry

**How to make credible:**

- Specific metrics (25%, not "significant")
- Technical details (shows real work)
- Industry context (AdTech, FinTech, etc.)
- Approximate scale (70TB/day)

---

### Type 3: Disguised Case Study (Bronze — Still Useful)

**What it is:** Heavily generalized story, no identifying details.

**Example:**

> "A scale-up with fragmented data across 5 tools needed a unified platform. We delivered architecture, PoC, and handover documentation in 8 weeks."

**When to use:**

- Very sensitive client
- Early in relationship (can upgrade later)
- Learning project (not best work)

**Less credible but still useful for:**

- Showing you've done the work
- Illustrating your process
- Filling portfolio early on

---

### Type 4: Employment-Based Case (Using Past Work)

**What it is:** Work done as employee, positioned as experience (not seniuts.com project).

**Example:**

> "At Appodeal, I led a Spark optimization initiative that reduced Databricks compute costs by 25% on a 70–80TB/day platform."

**How to use:**

- "In my previous role at [Company]..."
- "Before starting seniuts.com, I..."
- Focus on what YOU did, not the company

**Limitations:**

- Can't claim it was a consulting project
- Can't use client's name without permission
- Must be honest about context

## Case Study Template

### Structure (1-page format)

```
[HEADER]
Title: "[Problem] for [Industry/Type]"
Subtitle: [Key result in one line]
Duration: [X weeks]
Services: [Audit / PoC / Launch]

[CONTEXT]
Client: [Industry, size, anonymized description]
Situation: [2–3 sentences on the starting point]
Challenge: [1–2 sentences on the specific problem]

[SOLUTION]
Approach: [2–3 sentences on what seniuts.com did]
Key activities:
- [Activity 1]
- [Activity 2]
- [Activity 3]
Technologies: [List of relevant tech]

[RESULTS]
Outcome: [Primary metric or achievement]
Additional results:
- [Result 1]
- [Result 2]
Impact: [1 sentence on business value]

[QUOTE] (if available)
"[Client quote]" — [Name, Title] (or "Client stakeholder")

[CTA]
Want similar results? Book an Architecture Audit.
```

## When to Ask for Case Studies

### Timing

| Project Phase      | Ask For                                                     |
| ------------------ | ----------------------------------------------------------- |
| **Kickoff**        | Permission to anonymized case study (set expectation early) |
| **Mid-project**    | Capture metrics, take notes for case study                  |
| **Project end**    | Draft case study, ask for approval                          |
| **1 month later**  | Ask for testimonial quote                                   |
| **3 months later** | Ask for referral                                            |

### Script for Asking (End of Project)

**Email template:**

```
Subject: Quick favor — case study?

Hi [Client Name],

Thanks again for the opportunity to work on [project]. I'm really happy with how it turned out.

I'm building my consulting practice and case studies are incredibly valuable. Would you be open to me writing a short case study about our work?

I can:
- Keep it anonymized (no company name)
- Share a draft for your approval before publishing
- Keep technical details vague if sensitive

It would just describe the challenge, approach, and results — similar to what I'd tell a future prospect in conversation.

Let me know if this works, and I'll send a draft for you to review.

Best,
Vasili
```

## Case Studies from Employment

### Using Past Work Ethically

**Appodeal case (anonymized example):**

| What I can say                           | What I cannot say                |
| ---------------------------------------- | -------------------------------- |
| "AdTech platform processing 70–80TB/day" | "Appodeal" (unless permitted)    |
| "Reduced Spark costs by 25%"             | Exact dollar amounts             |
| "I led the optimization initiative"      | "seniuts.com delivered this"     |
| Technical details (configs, patterns)    | Proprietary code or architecture |

**How to position:**

> "Before starting seniuts.com, I worked as a Senior Data Engineer at an AdTech company where I led a Spark cost optimization initiative..."

This is honest and uses real experience.

## Case Study Collection Process

### For Each Engagement

**During project:**

- [ ] Document starting metrics (costs, time, errors)
- [ ] Take notes on key decisions and challenges
- [ ] Capture "before/after" where possible
- [ ] Save anonymized architecture diagrams

**At project end:**

- [ ] Calculate results (% improvement, time saved, cost reduced)
- [ ] Draft case study (1 page)
- [ ] Send to client for approval
- [ ] Ask for testimonial quote

**After approval:**

- [ ] Publish on website
- [ ] Create LinkedIn post version
- [ ] Add to sales deck
- [ ] Update one-pager

## Testimonial Collection

### Testimonial vs Case Study

| Asset           | Content            | Effort | Value     |
| --------------- | ------------------ | ------ | --------- |
| **Case study**  | Story with details | Medium | High      |
| **Testimonial** | 1–3 sentence quote | Low    | Very High |

### Testimonial Template

Ask client to answer ONE of these:

- "What was the biggest impact of working with Vasili?"
- "How would you describe working with seniuts.com?"
- "What would you tell someone considering hiring Vasili?"

### Where to Use Testimonials

- Website homepage
- About page
- Case study pages
- One-pager PDF
- LinkedIn profile (recommendations)
- Proposal documents

## Legal Considerations

### Before Publishing Any Case Study

- [ ] No NDA violation
- [ ] Client approval (email confirmation is sufficient)
- [ ] No proprietary information disclosed
- [ ] No revenue/financial details without permission
- [ ] Anonymized sufficiently if required

### NDA Best Practices

When signing client NDA:

- Check if marketing/case study use is allowed
- Ask for carve-out: "anonymized case studies permitted"
- If no carve-out, ask explicitly via email after project

## Anonymization Checklist

Before publishing anonymized case:

- [ ] Company name removed
- [ ] Individual names removed
- [ ] Exact dates generalized ("Q2 2024" → "early 2024")
- [ ] Revenue/user numbers generalized ("€2M" → "7-figure revenue")
- [ ] Industry clear but company not identifiable
- [ ] Tech stack okay to mention (usually fine)
- [ ] Metrics okay to share (confirm with client)
