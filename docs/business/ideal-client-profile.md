# Ideal Client Profiles

## Overview

seniuts serves four primary client profiles:

1. **Direct clients**: Scale-ups and mid-size companies with data platform needs
2. **Software house partners**: Development shops that need data engineering expertise
3. **Cloud/DevOps consultancy partners**: Infrastructure consultancies that need data platform support
4. **Fractional leadership clients**: Companies that need part-time technical data leadership

---

## ICP 1: Scale-up / Mid-size Company with Data Chaos

### Profile

| Attribute         | Description                                                             |
| ----------------- | ----------------------------------------------------------------------- |
| **Company size**  | 50–500 employees                                                        |
| **Stage**         | Series A–C, or established mid-size company                             |
| **Data team**     | 0–3 data engineers, or no dedicated team                                |
| **Data maturity** | Early or chaotic                                                        |
| **Budget**        | Has budget for platform investment, but needs clarity before committing |

### Signs They Need Help

- Data is spread across tools, databases, and manual exports
- Pipelines break often and nobody fully owns them
- Reporting is slow or unreliable
- No clear data architecture or roadmap
- Hiring a data team but no one to define the foundation
- Previous attempts failed or stalled
- Leadership frustrated with data quality and delivery speed

### Buying Trigger

- New CTO/Head of Data joins and wants to clean up
- Board or investors ask about data strategy
- Key reporting or analytics initiative blocked
- Failed internal or vendor project
- Scaling pressure exposes data fragility
- Compliance or audit requirement

### Decision Maker

- CTO
- Head of Data / VP Data
- VP Engineering
- COO / Founder (in smaller companies)

### Pain Points

- No architecture roadmap
- No data ownership
- Fragile pipelines
- Slow or unreliable reporting
- Expensive or unreliable Spark/Airflow/Kafka workloads
- Missing data quality checks
- Missing observability and runbooks
- Fear of long-term vendor dependency

### What to Offer First

**Architecture & Strategy Audit**

- Low commitment entry point
- Delivers clarity before larger investment
- Positions seniuts as trusted advisor

### What NOT to Offer First

- Full platform build (too risky without discovery)
- Long-term retainer (no trust established)
- Generic consulting hours

### Outreach Angle

> "Most scale-ups I talk to have data spread across too many tools, and no one owns the foundation. If you're planning to hire a data team or invest in a platform, it usually helps to have the architecture sorted first. I help companies get clarity before committing to a larger build."

### Example First Message Angle

> "I noticed [Company] is scaling quickly. A lot of companies at this stage hit data chaos — pipelines break, reporting is slow, and no one owns the foundation. I help CTOs and Heads of Data get architecture clarity before committing to a bigger platform investment. Would a short call make sense?"

### Qualification Questions

1. What does your current data stack look like?
2. Who owns data infrastructure today?
3. What's the biggest data-related blocker right now?
4. Are you planning to hire a data team or build a platform?
5. Have you tried to fix this before? What happened?
6. What's the timeline for making a decision?

## ICP 2: Software House Needing Data Platform Expertise

### Profile

| Attribute           | Description                                           |
| ------------------- | ----------------------------------------------------- |
| **Company type**    | Custom software development agency                    |
| **Size**            | 20–200 developers                                     |
| **Data capability** | Limited or no dedicated data engineering team         |
| **Client work**     | Builds applications, backends, sometimes touches data |

### Signs They Need Help

- Client project requires data platform work
- No internal data engineering expertise
- Previous data projects delivered poorly or over budget
- Client asking for data pipelines, analytics, or platform work
- Want to expand service offering but lack capability

### Buying Trigger

- Active client project with data platform scope
- Lost a deal because of missing data capability
- Client RFP includes data requirements
- Internal initiative to build data practice

### Decision Maker

- CTO
- Delivery Director
- Head of Engineering
- Partner / Owner

### Pain Points

- Cannot deliver data platform work confidently
- Risk of failed delivery on client projects
- Want to expand offering without hiring full-time
- Need senior expertise to guide junior developers

### What to Offer First

**Partnership introduction / Architecture support**

- Position as their data platform partner
- Offer to support client discovery and architecture
- Joint delivery model

### What NOT to Offer First

- Competing for their clients
- Long-term commitment before first project
- Hourly work without clear scope

### Outreach Angle

> "Software houses often get asked to build data pipelines or platforms, but it's not their core strength. I partner with development shops to handle the data architecture and delivery side — so you can say yes to those projects without the risk of failed delivery."

### Example First Message Angle

> "I work with software houses that occasionally need data platform expertise for client projects — architecture, pipelines, Spark, Airflow, cloud data platforms. If you ever have a project where that would help, I'd be happy to chat about how a partnership could work."

### Qualification Questions

1. Do you get client requests for data platform work?
2. How do you handle those today?
3. Have you had any data projects go poorly?
4. Would you be open to a partnership model for data work?
5. Is there a current project where this might be relevant?

## ICP 3: Cloud / DevOps Consultancy Needing Data Engineering Partner

### Profile

| Attribute           | Description                                 |
| ------------------- | ------------------------------------------- |
| **Company type**    | Cloud infrastructure or DevOps consultancy  |
| **Size**            | 10–100 consultants                          |
| **Expertise**       | AWS, Azure, Kubernetes, Terraform, CI/CD    |
| **Data capability** | Limited — they do infra, not data pipelines |

### Signs They Need Help

- Client needs data platform on top of cloud infrastructure
- Airflow, Spark, Kafka, Databricks, or Snowflake in scope
- Client wants data lakehouse or data warehouse
- DevOps team asked to support data workloads they don't understand

### Buying Trigger

- Active client project with data scope
- Client asking for data engineering support
- Platform work expanding into data territory

### Decision Maker

- Founder / Partner
- Head of Delivery
- Principal Consultant

### Pain Points

- Cannot deliver data platform work
- Data workloads different from infrastructure work
- Risk of failed delivery
- Client expects end-to-end solution

### What to Offer First

**Partnership introduction / Joint architecture**

- Position as their data platform partner
- Handle data layer while they handle infra
- Joint client delivery

### What NOT to Offer First

- Infrastructure work (their domain)
- Taking over client relationship
- Long-term commitment before first project

### Outreach Angle

> "Cloud and DevOps consultancies often get pulled into data platform work — Spark, Airflow, data pipelines — but it's not what they specialize in. I partner with infrastructure consultancies to handle the data layer when projects need it."

### Example First Message Angle

> "I noticed [Company] does cloud infrastructure and DevOps. If you ever have a client project that touches data platforms — Spark, Airflow, lakehouse, pipelines — I'd be happy to discuss a partnership. I handle the data engineering side while you handle infrastructure."

### Qualification Questions

1. Do your clients ever ask for data platform work?
2. How do you handle that today?
3. Would you be open to partnering with a data engineer for those projects?
4. Is there a current project where this might be relevant?

## ICP 4: Company Needing Fractional Technical Data Lead

### Profile

| Attribute          | Description                                     |
| ------------------ | ----------------------------------------------- |
| **Company size**   | 30–300 employees                                |
| **Data team**      | 1–5 data engineers, or hiring                   |
| **Data maturity**  | Building or scaling                             |
| **Leadership gap** | No senior data leader, or leader stretched thin |

### Signs They Need Help

- Building a data team but no senior technical leader
- Data engineers need guidance and code review
- Architecture decisions being made without senior input
- CTO/VP Engineering covering data but not deep in it
- Previous tech lead left

### Buying Trigger

- Hiring first data engineers
- Data team growing but no lead
- Key person left
- CTO needs to offload data decisions

### Decision Maker

- CTO
- VP Engineering
- Head of Data

### Pain Points

- No senior data leadership
- Junior team needs mentoring
- Architecture decisions stuck
- CTO stretched too thin
- Hiring without clear technical vision

### What to Offer First

**Fractional Technical Data Lead engagement**

- Part-time embedded leadership
- Architecture decisions, code review, mentoring
- Hiring support

### What NOT to Offer First

- Full-time commitment
- Delivery work without leadership scope
- Long-term contract before proving value

### Outreach Angle

> "Companies building their first data team often don't have a senior technical lead to guide architecture and mentor engineers. I work as a fractional Technical Data Lead — embedded part-time to handle architecture decisions, code review, and team guidance until you're ready to hire full-time leadership."

### Example First Message Angle

> "I noticed [Company] is growing and might be building out data capabilities. A lot of companies at this stage need senior technical guidance but aren't ready for a full-time data lead. I work as a fractional Technical Data Lead — would that ever be useful for you?"

### Qualification Questions

1. Do you have a data team today?
2. Who handles architecture decisions for data?
3. Is the team getting the technical guidance they need?
4. Are you planning to hire a senior data lead?
5. Would part-time embedded leadership help in the meantime?
