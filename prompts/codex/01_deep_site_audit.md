## Context

This website is for **seniuts.com**, a data consulting company.

The main business idea:

- Data architecture consulting
- Data platform strategy
- PoC / MVP delivery
- Launch & Transfer model
- Team enablement
- Clean handover to the client
- Optional short-term stabilization support

The company must not look like:

- a freelancer profile
- a generic outsourcing company
- a staffing agency
- a long-term project owner

The company should look like:

- a boutique data consulting company
- a practical data architecture partner
- a launch partner for production-ready data platforms
- a handover-first consulting company

## Audit areas

Please review the website across these areas:

### 1. Positioning

Check whether the site clearly explains:

- what seniuts.com does
- who the target customer is
- what problem is solved
- why the Launch & Transfer model matters
- why a client should start with an Architecture Audit

### 2. Website structure

Check whether the current pages are enough:

- Home
- Services
- About
- Contact
- optional Case Studies / Insights

Recommend missing pages or sections only if they are useful.

### 3. Copywriting

Review all public-facing copy.

Check for:

- clarity
- conciseness
- premium tone
- excessive buzzwords
- unclear claims
- weak CTAs
- too much focus on the founder instead of client outcomes

### 4. UX and readability

Check:

- hierarchy
- spacing
- section order
- CTA visibility
- mobile readability
- navigation
- whether a busy CTO can understand the offer in under 30 seconds

### 5. Visual design

Check:

- typography
- color usage
- consistency
- layout
- spacing
- visual clutter
- whether the site looks professional and trustworthy

### 6. Technical quality

Check:

- framework and router
- project structure
- component reuse
- styling conventions
- accessibility basics
- metadata / SEO basics
- performance risks
- package scripts
- build / lint / type-check availability

### 7. Maintainability

Check whether the site is easy for a technical founder to maintain.

Prefer:

- simple components
- clear content structure
- minimal dependencies
- reusable sections
- easy editing

Avoid:

- over-engineering
- unnecessary state management
- excessive abstraction
- hardcoded duplicated blocks if they are likely to change often
